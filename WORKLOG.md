# Рабочий журнал — MegaPixel Store

## Обзор проекта
Интернет-магазин мобильных телефонов MegaPixel (megapixel.by) на Next.js 16.2.9 + React 19 + Tailwind CSS 4. Данные товаров хранятся локально в JSON (экспорт WooCommerce), без внешней базы данных.

**Директория проекта:** `C:\Users\vadim\Desktop\Смартфоны\megapixel-store`
**Порт:** 3000

---

## Технологический стек
- Next.js 16.2.9 (App Router, Turbopack)
- React 19.2.4
- Tailwind CSS 4
- TypeScript 5
- Данные: `src/data/products.json` (~500 товаров, импорт с megapixel.by)
- Изображения: `public/images/` (~2150 файлов .webp)
- Заказы: `src/data/orders.json` (file-based)

### Сравнение товаров
- Кнопка на карточке товара (↔ иконка)

- Парсинг HTML-описаний в характеристики
- Группировка по разделам (Экран, Процессор, Память, Камера и т.д.)

### Админ-панель (`/admin`)
- **Вход** — пароль `megapixel2026` (cookie-based)
- **Заказы** (`/admin/orders`) — список, фильтр по статусу, смена статуса, комментарий, удаление, бейдж «1 клик»
- **Товары** (`/admin/products`) — список, поиск, добавление/редактирование, включение/выключение видимости, удаление
  - Тип товара: Простой / Вариативный
  - Категории — иерархический dropdown (optgroup) + кнопка «+» для добавления новых
  - Изображения — загрузка до 10 шт, превью, перестановка порядка, удаление
  - Характеристики — label/value с быстрыми кнопками (ОЗУ, память, цвет, процессор и др.)
  - Атрибуты (для вариативных) — теги значений, чекбоксы «Виден» / «Для вариаций»
  - Вариации — генерация из атрибутов или добавление вручную, цена/скидка для каждой

### API
- `GET /api/search?q=` — поиск товаров
- `POST /api/orders` — создание заказа
- `GET /api/admin/orders` — список заказов (авторизация)
- `PATCH /api/admin/orders` — смена статуса/комментария
- `DELETE /api/admin/orders` — удаление заказа
- `GET /api/admin/products` — список товаров (авторизация)
- `POST /api/admin/products` — добавление товара
- `PUT /api/admin/products` — редактирование товара
- `PATCH /api/admin/products` — переключение видимости
- `DELETE /api/admin/products` — удаление товара
- `POST /api/admin/upload` — загрузка изображений (авторизация)

## Запуск

### Dev-режим (Turbopack, горячая перезагрузка) — только для десктопа!
```bash
# bat-файл: start-dev.bat
node node_modules\next\dist\bin\next dev --hostname 0.0.0.0
```
**ВНИМАНИЕ**: Turbopack dev-сервер НЕ работает на телефонах (WebSocket HMR падает). Использовать только на компьютере.

### Production-режим (для теста на телефонах)
```bash
# bat-файл: start-prod.bat
npx next build
node node_modules\next\dist\bin\next start -p 3000 -H 0.0.0.0
```
Production-режим работает на всех устройствах. После изменений в коде нужно пересобирать (`next build`).

### Доступ с телефона
Адрес: `http://<IP_компа>:3000` (например, `http://192.168.0.106:3000`)

## Деплой и хостинг

### Решение: VPS на hoster.by
- Текущий тариф «Wordpress № 2» (ID 161240) — shared PHP, **не подходит** для Next.js
- Решение: заказать **облачный сервер (VPS)** на hoster.by
- Стоимость: ~35 BYN/мес (со скидкой 30% на первые 6 мес)
- Конфигурация: 1 vCPU, 1 ГБ RAM, SSD 10 ГБ, 1 IP
- Оплачен до: 16.02.2028

### Почему не Vercel
- Vercel Pro = $20/мес (для коммерческих проектов)
- VPS hoster.by = ~$11/мес — дешевле в 2 раза
- VPS даёт полный контроль над сервером

### Следующие шаги для деплоя
1. Заказать VPS в конфигураторе hoster.by (Облачные серверы)
2. Получить SSH-доступ (IP, логин, пароль)
3. Установить: Ubuntu, Node.js 20+, nginx, certbot
4. Загрузить файлы проекта через SCP/SFTP
5. `npm run build && npm run start`
6. Настроить nginx (прокси на порт 3000)
7. Настроить SSL (Let's Encrypt через certbot)
8. Подключить домен (DNS A-запись → IP сервера)

**Решение**: `next build && next start -H 0.0.0.0` (production-режим, без Turbopack). Созданы bat-файлы:
- `start-dev.bat` — Turbopack dev-режим (для десктопа)

```cmd
# ПРАВИЛЬНО:
cmd /c "taskkill /F /IM node.exe 2>nul"
```

### Проблема

```powershell
[System.Environment]::SetEnvironmentVariable("SHELL", "C:\Windows\System32\cmd.exe", "User")
```

Это заставляет MiMoCode использовать `cmd.exe` вместо PowerShell **всегда**, для всех новых сессий. Переживает перезапуск компьютера.

### Что обновлено

3. **AGENTS.md** — обновлена документация с корневой причиной и permanent fix

### Важно
- Текущая сессия MiMoCode использует старый shell (PowerShell) — изменение вступит в силу после перезапуска
- `NO_COLOR=1` и `TERM=dumb` в bat-файлах больше НЕ нужны — cmd.exe не генерирует escape-коды

## 2026-07-23 — Полное исправление проблемы с ломанием терминала

### Проблема

Терминал продолжал ломаться (mouse-tracking escape-коды `[555;135;47M...`) несмотря на все предыдущие попытки исправления:
1. `.vscode/settings.json` — переключил терминал по умолчанию на Command Prompt → не помогло
2. `SHELL=C:\Windows\System32\cmd.exe` — permanent env var → не помогло
3. `NO_COLOR=1`, `TERM=dumb` — отключили цвета → не помогло

### Корневая причина (точная)

**Env vars (`SHELL`, `NO_COLOR`, `TERM`) — это НЕ решение проблемы.** Они отключают цвета и меняют shell для MiMoCode, но НЕ предотвращают mouse-tracking.

Mouse-tracking (`ESC[?1000h`) включается **процессом node** при запуске. Когда процесс умирает (особенно через `taskkill /F`), он не успевает отправить `ESC[?1000l` (выключение). Терминал остаётся в режиме мыши → любой вывод = мусор.

**Команда, которая ломает терминал:**
```
cmd /c "taskkill /F /IM node.exe 2>nul"
```
Убивает node с `/F` (force) → процесс не очищает терминал.

### Решение

Создан скрипт `reset-terminal.bat`, который отправляет escape-последовательности для отключения mouse-tracking:
```batch
@echo off
node -e "process.stderr.write('\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l\x1b[?1015l')"
```

**Правило:** ПОСЛЕ ЛЮБОЙ команды, запускающей node/npx/next, ВЫЗЫВАТЬ `reset-terminal.bat`.

## 2026-07-23 — Диагностика: почему reset-terminal.bat не работал

### Проблема

Смена shell на cmd.exe не решила проблему с mouse-tracking. После запуска команд через MiMo терминал продолжал ломаться — мусор `^[[<35;39;45M...` при движении мыши.

### Корневая причина (точная)

**`reset-terminal.bat` использовал `node -e` для отправки escape-кодов.** Node при запуске сам включает mouse-tracking (`ESC[?1000h`). Bat-файл пытался выключить mouse-tracking через node, но node тут же включал его обратно.

Цепочка:
```
node -e запускается
  → node включает mouse-tracking (ESC[?1000h)
    → node пишет ESC[?1000l (выключение)
      → node завершается
        → mouse-tracking остаётся активным
```

### Решение

Bat-файлы переписаны **без node**. Используется встроенная возможность cmd:
```bat
for /f %%a in ('echo prompt $E ^| cmd') do set "ESC=%%a"
<nul set /p ="%ESC%[?1000l%ESC%[?1002l%ESC%[?1003l%ESC%[?1006l%ESC%[?1015l"
```

`echo prompt $E | cmd` возвращает ESC-символ (ASCII 27). `set /p` выводит escape-последовательность без перевода строки. Никакого node — mouse-tracking выключается чисто через cmd.

### Изменённые файлы

| Файл | Изменение |
|------|-----------|
| `reset-terminal.bat` | Убран `node -e`, используется `echo prompt $E` |
| `kill-and-reset.bat` | Убран `node -e`, используется `echo prompt $E` |
| `AGENTS.md` | Добавлено правило: NEVER use `node -e` in reset scripts |
